# Kenga — спецификация языка для человека

Статус: описывает **портативное подмножество** Kenga — то, что исполняется
одинаково на полном Rust-VM и в bootstrap-раннере `bootstrap/bin/kenga-lite.exe`.
Грамматика в коде: `src/parser.rs` (тесты: `tests/lang.rs`), примеры:
`examples/ml/kenga_seed_*.kenga` (базовое), `kenga/emit/rt_*.kenga` (продвинутое).
Справочник по полному языку: `docs/LANGUAGE.md`.

## 1. Философия

**Self-hosting.** Kenga существует не «рядом с» своим компилятором, а ради его
переписывания. Сегодняшний Rust-компилятор (`src/*.rs`) — временный строительный
кран: целевая цепочка — `examples/selfhost/kenga_lite.kenga` (компилятор lite-диалекта,
написанный на самой Kenga) → `kenga emit-c` → чистый C99 → `bootstrap/kenga-lite.exe`,
который уже ничего не знает про Rust. Каждая новая конструкция языка обязана рано
или поздно доехать до этой лестницы (шаги 1–13 описаны в `docs/SELFHOST.md`),
иначе она навсегда останется фичей хоста, а не языка.

**Verifier-first.** Конструкция языка обязана исполняться на `kenga-lite`, не только парситься legacy-хостом. Иначе это фича крана, а не языка.

**Tiny-model-friendly.** Словарь языка нарочно маленький: ключевые слова и скобки — отдельные атомы, остальное по буквам. Так проще писать и проще учить короткие программы.
Это делает язык удобной целью для микро-моделей (Prophet): грамматика сознательно
мала, новых терминалов почти не требуется (`enum` = 3 токена, `match` = 5 — уже
представимы без переучивания кодека). Цена расширения синтаксиса считается в
токенах, и она входит в дизайн-решение по каждой фиче.

## 2. Лексика

| Категория | Правило |
|---|---|
| Идентификаторы | `[a-zA-Z_][a-zA-Z0-9_]*`, регистрозависимы |
| Целочисленный литерал | десятичные цифры: `0`, `42`; полный компилятор также понимает `0x…` / `0b…` |
| Строковый литерал | `"текст"`, внутри escape `\n` `\t` `\\` `\"` |
| Списковый литерал | `[expr, expr, ...]`, в т.ч. пустой `[]` |
| Комментарии | `//` до конца строки (полный компилятор дополнительно понимает `/* … */`) |
| Разделитель операторов | `;` |

Ключевые слова портативного ядра: `fn let if else while for in return true false`
плюс имена типов `i64 str list`. `true`/`false` — литералы, ведут себя как `1`/`0`.

## 3. Типы

| Тип | Значение | Примечание |
|---|---|---|
| `i64` | целое со знаком | основной числовой тип; `/` и `%` — целочисленные |
| `str` | строка | иммутабельна: операции возвращают новую строку |
| `list` | список значений | см. §8 |

Аннотации типов опциональны: `let x: i64 = 1;` эквивалентно `let x = 1;`.
В kenga-lite аннотации игнорируются (значения тегированы в runtime).

**Экспериментальные типы/конструкции** — `enum`, `match`, `union`, `struct`,
`f64`, события (`on`/`emit`/`pump`), импорты: они есть в Rust-компиляторе
(см. `tests/lang.rs`: `bitwise_ops`, `event_loop_on_emit_pump`, `import_stdlib_and_struct`)
и частично уже в `kenga-lite.exe`, но их ещё нет в self-host исходнике
`kenga/compiler/lite.kenga`. Не используйте их в коде, который должен жить на
всей лестнице, пока соответствующая ступень не пройдена (статус: `docs/ROADMAP.md`).

## 4. Операторы и приоритет

От высшего к низшему:

| Приоритет | Операторы | Пример |
|---|---|---|
| 1 (высший) | унарные `-` `!` `~` | `-x`, `!flag` |
| 2 | `*` `/` `%` | `a * b / c` |
| 3 | `+` `-` | `a + b - c` (для `str`/`str` — конкатенация) |
| 4 | `<<` `>>` | `x << 4` |
| 5 | `<` `<=` `>` `>=` | `a <= b` |
| 6 | `==` `!=` | `a == b` |
| 7 | `&` `^` `\|` | `mask & 0xF0` |
| 8 (низший) | `&&` `\|\|` | `a > 0 && b > 0` |

Результат сравнения — `i64`: `0` или `1`. Условия в `if`/`while` истинны, когда
не равны `0`.

Нюансы переносимости:
- битовые операторы и сдвиги определены только для `i64`; `0x`/`0b` — целые
  литералы. lite / more / lower_c / bc_src_c: `examples/selfhost/bitops.kenga`,
  `examples/selfhost/hex_lab.kenga`;
- `&&`/`\|\|`/`!` считаются как 0/1. Короткое замыкание: lite C VM (`eval` /
  selftest), more (`kenga-lite run`) и `bc_src_c` — JMPF skip правого
  операнда; `lower_c` — C `&&`/`||`.
- скобки меняют приоритет как обычно: `(1 + 2) * 3 == 9`.

## 5. Инструкции

```kenga
let x = expr;          // объявление без типа
let x: i64 = expr;     // объявление с аннотацией типа
x = x + 1;             // присваивание существующей переменной
xs[i] = v;             // присваивание элементу списка
if cond { ... } else if cond2 { ... } else { ... }
while cond { ... }
for v in xs { ... }    // обход списка
for i in 0..10 { ... } // диапазон [0, 10)
break;                 // выход из цикла
continue;              // следующая итерация
return expr;           // возврат значения из функции
println(expr);         // печать значения + перевод строки
```

Особенности:
- `let` создаёт переменную в текущей функции; повторный `let` с тем же именем
  затеняет предыдущую привязку — не полагайтесь на это в переносимом коде.
- `for`/`break`/`continue` работают на полном VM и в `kenga-lite.exe`
  (`examples/selfhost/for_lite.kenga`), но **не поддержаны** self-host
  компилятором `kenga/compiler/lite.kenga` — там только `while`.
- `println` печатает `i64`, `str`, `list` (формат `[a, b, c]`) и struct;
  у `print` тот же вывод без перевода строки.

## 6. Функции

```kenga
fn имя(a: i64, b: i64) -> i64 {
    return a + b;
}
```

- Вызов: `имя(аргументы)` — обычное выражение, можно в любом выражении.
- Параметры передаются **по значению** (числа копируются; списки копируются
  как handle — мутация элементов параметра видна снаружи).
- Рекурсия разрешена: `fn fib(n) { if n < 2 { return n; } return fib(n-1) + fib(n-2); }`
  (`examples/ml/kenga_seed_fib.kenga`).
- **Порядок определений свободный**: kenga-lite собирает все имена функций до
  компиляции тел, forward references работают (проверено: `compile_lite` в
  `kenga/compiler/lite.kenga` заполняет `fnames` до эмиссии). Урок
  `examples/tour/03_fn.kenga` демонстрирует вызов функции, объявленной ниже.
- Тело — последовательность инструкций в `{}`; функция без явного `return`
  возвращает значение последнего выражения (lite-стиль: `fn add(a, b) { a + b }`),
  но в переносимом коде всегда пишите `return`.

## 7. Строки

| Операция | Синтаксис | Результат |
|---|---|---|
| Конкатенация | `s + t` | новая строка |
| Длина | `len(s)` | `i64` |
| Индексация | `s[i]` | **строка из одного символа**, не число |
| Сравнение | `==`, `!=` | `0`/`1`, посимвольное |
| Код символа | `ord(ch)` | код первого символа, `i64` |

Строки иммутабельны: «изменение» — это сборка новой строки конкатенацией.
Индексация выходит за границы → ошибка времени выполнения.
Пример: `examples/selfhost/bc_str.kenga`, `examples/tour/06_strings.kenga`.

## 8. Списки

| Операция | Синтаксис | Примечание |
|---|---|---|
| Литерал | `[10, 20, 30]`, `[]` | элементы — любые выражения |
| Чтение | `xs[i]` | индексация с нуля |
| Перезапись | `xs[i] = v` | мутирует существующий слот |
| Размер | `len(xs)` | `i64` |
| Рост | `push(xs, v)` | встроенная функция, возвращает **новый** список: `xs = push(xs, v);` |

Метода `append` **нет** — рост списка только через `push` в функциональном стиле.
На актуальном `kenga-lite.exe` (tagged KVal runtime) списки гетерогенны и
вложенны: `[[1, 2], "три"]` допустимо (`examples/selfhost/nested_lists.kenga`);
на старых путях lite списки были строго `i64` — для переносимого кода держите
списки однородными. `println(xs)` печатает список целиком: `[10, 20, 30]`.
Пример: `examples/tour/07_lists.kenga`, `examples/native_lists.kenga`.

## 9. Программа

- Точка входа — функция **`main` без параметров**, обязательна во всех диалектах.
- Возвращаемое значение `main` — результат программы: `return 0;` означает успех,
  ненулевой код — ошибку (rc-семантика Unix); именно его печатает тестовый harness
  и возвращает процесс.
- Файл — просто набор `fn` (опционально экспериментальных items); порядок свободный.
- Ошибки времени выполнения (деление на ноль, выход за границы, assert) завершают
  процесс с ненулевым rc и сообщением в stderr.

## 10. Отличия lite от полного компилятора

Колонки: **Rust VM** = `cargo run` / `kenga run` (полный компилятор);
**lite-exe** = `bootstrap/bin/kenga-lite.exe` / `kenga run --lite`;
**self-host src** = диалект, который реально компилирует `kenga/compiler/lite.kenga`.

| Возможность | Rust VM | lite-exe | self-host src |
|---|---|---|---|
| `fn`/`let`/`if`/`else`/`while`/`return`, вызовы, рекурсия | да | да | да |
| `i64` арифметика и сравнения, `%` | да | да | да |
| строки: concat, `len`, `s[i]`, `==`, escape | да | да | да¹ |
| списки: литерал, `len`, `xs[i]`, `push` | да | да | да² |
| `for` / диапазоны `a..b` / `break` / `continue` | да | да | **нет** |
| `else if` | да | да | вложенным `if`³ |
| `f64`, `round` | да | да | нет⁴ |
| `struct` | да | да | нет |
| `import` | да | нет | нет |
| события `on`/`emit`/`pump` | да | да | нет |
| Tensor / Prophet Memory / tape | да | да | нет |
| `enum` / `match` / `union` | эксперимент. | нет | нет |
| битовые `& ^ \| ~ << >>` | да | да | нет |

¹ строки нужны самому компилятору lite, поэтому они в ядре лестницы.
² списки `i64` — рабочая лошадка self-host VM (`stack`, `slots` — списки).
³ `else if` записывается как `else { if ... { } }` — семантика та же.
⁴ `f64` добавлен в `kenga_more.kenga` (ступень 9 лестницы).

Правило переноса: программа, использующая только колонки «да» во всех трёх,
запускается везде. Уроки `examples/tour/` соблюдают это правило (единственное
исключение — `for`, которого мы сознательно избегаем в пользу `while`).
