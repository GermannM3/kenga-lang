## EXECUTIVE SUMMARY (раздать как одну страницу до начала)

**Kenga — верифицируемая нейро-символическая среда**: предметно-ориентированный язык,
самохостящийся компилятор, рантайм-верификатор и фабрика обучающих данных,
спроектированные совместно так, чтобы **крошечные модели (≈0.8M параметров) на CPU
решали задачи, недоступные моделям в 1000 раз больше**, обученным «в лоб».

Ключевое доказательство (измерено, опубликовано):
устранение статистического shortcut'а из обучающего распределения подняло
точность семантической привязки генерации с **5.6% до 98.6% (×17.6)** при
неизменной архитектуре и бюджете параметров.

Мы продаём не «ещё одну LLM». Мы продаём **метод производства дешёвых
верифицируемых экспертов под ваш DSL** — и стек, в котором этот метод уже
работает от языка до железа.

## СЛАЙД 1 — Проблема

**Три невыносимых расхода современной GenAI:**

```
1. Энергия/железо:  полезная задача на 1B+ модели = GPU-кластер
2. Данные:          для узкого DSL (SQL-диалект, смарт-контракты,
                    конфиги, робототехника) обучающих данных НЕТ
3. Доверие:         модель галлюцинирует, ответ нельзя проверить
```

- Edge-устройства не тянут инференс больших моделей
- Внутренние языки компаний не имеют корпусов вообще
- Выход модели невозможно верифицировать автоматически → человек в цикле → цена

**Заметка докладчика:** здесь не сравниваем себя с ChatGPT. Мы про другой класс задач:
узкий язык + ограниченное железо + требование проверяемости.

## СЛАЙД 2 — Решение: co-design языка и модели

```
   ЯЗЫК (учится быстро)  →  КОМПИЛЯТОР  →  РАНТАЙМ-ВЕРИФИКАТОР
            ↑                                        │
            │                                        ▼
     НЕЙРОМОДЕЛЬ (0.8M, CPU)  ←  ФАБРИКА ВЕРИФИЦИРОВАННЫХ ДАННЫХ
```

- **Язык спроектирован под выучиваемость микро-моделью**: 128-токенный кодек,
  регулярная детерминированная семантика
- **Каждая программа исполняется реальным рантаймом**: compile → run → stdout
  = объективный ground truth без разметки людьми
- **Фабрика порождает данные бесконечно**: программы + семантические
  эквиваленты + пары «сломано→исправлено» с классом ошибки

**Ключ:** модель и язык развиваются вместе — язык «стоит» ровно столько токенов,
сколько модель может выучить.

## СЛАЙД 3 — Главный результат: данные бьют размер

| | M5.2 (старое распределение) | **M5.3 (новое распределение)** |
|---|---|---|
| Параметры | 838K | **838K (без изменений)** |
| Обучение | одинаковый бюджет | одинаковый бюджет |
| **Semantic binding, compile** | 5.6% | **98.6% (×17.6)** |
| Шаблонная генерация compile | 92.5% | **100%** |

**Формула результата:** качество маленькой модели определяется не количеством
параметров, а тем, какие причинно-семантические зависимости вынуждено учить
распределение данных.

Опубликовано: HuggingFace (m5, m5-3), GitHub, полный цикл воспроизводится
на CPU за ~3 часа.

## СЛАЙД 4 — Второй результат: один маркер-токен = ×3.2 к ремонту кода

| Repair (исправление сломанного кода) | rp0 | **rp1** |
|---|---|---|
| Отличие | — | **один служебный токен границы задачи** |
| fixed@1 | 6.7% | **21.7% (×3.2)** |
| pass@4 | 21.7% | 28.3% |

Модель *умела* чинить — но не понимала, где кончается сломанный код.
Явная граница задачи решила это **без переобучения корпуса и архитектуры**.

**Применение у вас:** автоматический линкер/реставратор legacy-кода любого DSL.

## СЛАЙД 5 — Живой стек, а не презентационный прототип

```
Самохостинг:    13 ступеней; язык написан на себе;
                C99 — только bootstrap («строительные леса»)
Рантайм:        kenga-lite (C99, без зависимостей), режимы run/eval/chat
Верификатор:    каждая обучающая и каждый вывод модели проходят
                compile → run → stdout
Публикации:     HuggingFace (2 модели), GitHub (код, сплиты, манифесты),
                воспроизводимость на обычном CPU
Инфраструктура: краш-сейф пайплайны, rolling snapshots, run-manifests
                (git commit + sha256 корпуса в каждом артефакте)
```

## СЛАЙД 8 — Применения у покупателя

1. **Edge / offline AI** — эксперт-модель вашего DSL в мегабайтах, работает на CPU
2. **Copilot для внутренних языков** — SQL-диалекты, конфигурации, контракты,
   промпты агентских систем: там, где нет данных, но есть интерпретатор
3. **Supply-chain верификация моделей** — каждый чекпоинт имеет паспорт
   (корпус-hash, конфиг, метрики); поведение воспроизводимо юридически
4. **Self-repair пайплайн** — модель чинит свой же вывод, verifier решает,
   что принять (готовый контур, спецификация приложена)
5. **Образование** — бесконечные проверяемые упражнения по программированию

## СЛАЙД 10 — Ask

**Мы открыты к трём форматам:**

1. **Acquisition IP + команда** — стек целиком: язык, компилятор, рантайм,
   фабрика, модели, документация (27 инженерных документов)
2. **Пилот на вашем DSL** — 2–4 недели: ваша грамматика + ваш интерпретатор →
   верифицированный корпус + эксперт-модель ≤2M параметров под ваше железо.
   Критерий успеха формулируем вместе до старта
3. **Acqui-hire / исследовательское партнёрство** — направление
   verifier-gated self-learning (первый публичный эксперимент такого класса
   на микро-моделях готовится к запуску)

**Что нам нужно от вас:** доступ к вашей целевой модели/DSL и compute для
масштабной валидации метода.

## Три главных тезиса (повторить голосом)

1. «Мы не уменьшили GPT. Мы построили среду, где маленькая модель становится
   экспертом дёшево и проверяемо»
2. «×17.6 к решению задачи — изменением распределения данных, не размера модели»
3. «Каждая цифра в этой деке воспроизводится на ноутбуке без GPU»

## Подготовка к критическим вопросам

**Q: «Это игрушка 0.8M параметров. Где модель хотя бы на 1B?»**
A: «Верно, и это осознанно: наш результат — метод, независимый от масштаба.
Фабрика и verifier переносимы на ваш стек. Пилот на вашей задаче покажет
переносимость за 2–4 недели. Публичную репликацию на сторонней модели мы
открыто ставим в roadmap (слайд 9)».

**Q: «Почему бы просто не взять LoRA/fine-tuning большой модели?»**
A: «Для общего случая — берите LoRA. Наш метод закрывает то, чем LoRA не
занимается: (1) у вас НЕТ обучающих данных под ваш внутренний DSL — фабрика
их производит из вашего же интерпретатора; (2) вам нужен проверяемый вывод
на железе без GPU — наш контур даёт compile/run-гейт на каждом ответе;
(3) стоимость инференса копеечная — 0.8M параметров на CPU».

**Q: «Какой overhead у верификации?»**
A: «Верификация = запуск вашего же интерпретатора, миллисекунды на программу.
На нашем стенде: средний прогон 40–90 мс, включая запись файла и запуск процесса».

**Q: «Патенты?»**
A: «Публичная приоритетная фиксация: репозиторий с датами, HuggingFace
чекпоинты, полная воспроизводимость. Решение о патентных заявках примем
при сделке — раскрывать детали до NDA не будем» *(если спросят про статус —
честно: заявок нет, приоритет установлен публикациями)*.

**Q: «Команда?»**
A: «Один системный архитектор + AI-агенты как рабочие руки; вся серия
экспериментов M2→M6 выполнена за недели. При покупке команда расширяется
вашими инженерами — документы написаны как онбординг (SPEC, TOUR, 27 ADR)».

**Q: «Почему это купите вы, а не мы сами сделаете за квартал?»**
A: «Серия из шести контролируемых экспериментов, где каждый следующий ставился
по факту предыдущего (включая два отрицательных результата). Мы уже заплатили
за эти выводы временем; в деке — только проверенные шаги».
